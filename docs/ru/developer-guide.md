## Изменения интерфейса и установки Java

Если сервер не выбран, `Refresh` скрывает вкладки и показывает `NoSelectionPanel`. При создании сервера `ServerDialog` предлагает только редакции с импортированными шаблонами. Путь по умолчанию строится из `AppContext.BaseDirectory` и имени сервера и следует за изменениями имени, пока пользователь не укажет свой путь. `TemplateInstaller` создаёт родительскую папку перед подготовкой сервера. Для операций с неизвестным заранее объёмом работы используются неопределённые индикаторы выполнения без процента.

[`SimplePropertiesEditor.cs`](../../src/MinecraftServerManager/SimplePropertiesEditor.cs) строит переключатели и поля для частых параметров и прочих ключей существующего `server.properties`. Он переносит в текст файла только изменённые значения, сохраняя другие правки и комментарии. Простой и текстовый редакторы используют общий обработчик сохранения и одну копию `.bak`. Проверка несохранённых изменений охватывает оба редактора.

[`java-release.json`](../../installer/java-release.json) содержит закреплённые URL и SHA-256 Eclipse Temurin JRE 25. Скрипт сборки передаёт их Inno Setup. Страница установщика запускает [`JavaSetup.ps1`](../../installer/JavaSetup.ps1) в режиме `Detect` для определения текущей Java. После согласия пользователя установщик скачивает и проверяет архив, а скрипт в режиме `Install` проверяет основную версию, устанавливает Java в `%LOCALAPPDATA%\MinecraftServerManager\Java25`, обновляет пользовательские PATH и JAVA_HOME и записывает путь в `%APPDATA%\MinecraftServerManager\java.json`. [`JavaRuntime.cs`](../../src/MinecraftServerManager/JavaRuntime.cs) использует этот путь при создании Java-профилей и при запуске профилей с путём `java`. Java остаётся после удаления приложения. При смене закреплённого релиза согласуйте URL, контрольную сумму и проверку основной версии.

Документ описывает исходный код версии **0.2.1**. Minecraft Server Manager — локальное WPF-приложение под Windows 10/11 на .NET 10. Интерфейс использует пакет `MaterialDesignThemes` 5.2.1; локальный веб-сервер и внешняя база данных отсутствуют.

## Запуск и сборка

Из корня репозитория:

```powershell
dotnet restore src/MinecraftServerManager/MinecraftServerManager.csproj
dotnet build src/MinecraftServerManager/MinecraftServerManager.csproj
dotnet run --project src/MinecraftServerManager/MinecraftServerManager.csproj
```

Для сборки готового архива требуется PowerShell 7 (`pwsh`):

```powershell
pwsh ./scripts/Build-Release.ps1
```

Скрипт публикует автономное приложение для `win-x64` одним исполняемым файлом и создаёт ZIP в `dist`. Он прекращает работу, если каталог или архив этой версии уже существует. Значение `Version` задаётся в [файле проекта](../../src/MinecraftServerManager/MinecraftServerManager.csproj); при изменении версии обновляйте также [историю изменений](../../changelog.ru.md). GitHub Release создаётся и заполняется вручную; GitHub Actions в проекте нет.

Для сборки установщика Windows установите Inno Setup 6 и выполните:

```powershell
pwsh ./scripts/Build-Installer.ps1
```

Скрипт читает версию проекта, заново публикует автономную сборку `win-x64` и компилирует [`MinecraftServerManager.iss`](../../installer/MinecraftServerManager.iss) через `ISCC.exe`. При нестандартной установке Inno Setup передайте `-IsccPath`. Результат: `dist/MinecraftServerManager-v<версия>-win-x64-setup.exe`. По умолчанию существующий установщик не перезаписывается; при ошибке временные файлы остаются для диагностики. В установщик входят файлы опубликованного приложения без PDB и без серверных бинарных файлов Minecraft. Сценарий Inno Setup задаёт установку для текущего пользователя, требования Windows 10 и x64, русский и английский языки мастера, показ лицензии, ярлыки, обработку открытого приложения, запуск после установки и удаление. `AppId` должен оставаться постоянным при обновлениях. Профили, шаблоны, миры и резервные копии находятся вне каталога установки и при удалении сохраняются. EXE не подписан; для подтверждённого издателя нужна отдельная цифровая подпись.
Для повторной сборки той же версии передайте `-ReplaceExisting`: новый установщик компилируется до замены предыдущего файла.

| [`ServerDialog.cs`](../../src/MinecraftServerManager/ServerDialog.cs), [`TemplateSetupDialog.cs`](../../src/MinecraftServerManager/TemplateSetupDialog.cs), [`InlinePathBrowser.cs`](../../src/MinecraftServerManager/InlinePathBrowser.cs) | Встроенные формы и просмотр папок внутри главного окна; для выбора файлов и папок серверов используются системные диалоги. |
| [`UpdateChecker.cs`](../../src/MinecraftServerManager/UpdateChecker.cs) | Проверка последнего GitHub Release. |

`MainWindow` создаёт `ProfileStore`, `TemplateStore` и `ServerManager`. При запуске загружает профили, передаёт тот же список в менеджер для остановки всех процессов, а при отсутствии шаблонов открывает форму импорта. Таймер интерфейса обновляет отображение каждые две секунды; второй таймер раз в минуту проверяет расписание резервных копий. Событие `ServerManager.Changed` передаётся на UI-поток через `Dispatcher`.

Формы и подтверждения размещаются в `InlineOverlay` файла `MainWindow.xaml`. Элементы формы возвращают `Task<bool>` после сохранения или отмены; главное окно дожидается результата и убирает панель. Выбор ZIP/JAR выполняется через `OpenFileDialog`, выбор папки сервера — через `OpenFolderDialog`; оба системных окна Проводника принадлежат главному окну. Кнопка языка в панели первого запуска вызывает `Localization.SetLanguage`, а `MainWindow` синхронизирует выбор в боковой панели. Иконки используют `PackIcon` с общим стилем `UiIcon`; формы на C# используют `IconContent`. Формы приложения и подтверждения оставляйте внутри главного окна. Официальные ссылки на загрузку по-прежнему открываются в браузере. Все поверхности должны использовать тёмную палитру из `App.xaml`.

## Локализация

Английский язык используется по умолчанию. Выбор `en` или `ru` сохраняется в `%APPDATA%\MinecraftServerManager\settings.json`. `Localization.Instance` загружает настройку и встроенные словари JSON. В XAML применяется `{local:Loc Key}` с обновлением текста при переключении языка; в C# — `T("Key")` и `F("Key", значения...)` из глобального статического импорта. Каждую новую строку интерфейса добавляйте в **оба** файла: `Resources/en.json` и `Resources/ru.json`. Значения протокола сервера, пути и имена полей JSON не должны зависеть от языка.

После переключения языка главное окно пересчитывает статусы. Новые диалоги читают текущий язык. Уже записанные строки консоли остаются частью истории.

## Модель и файлы данных

`ServerProfile` содержит `Id`, `Name`, `Edition`, `Directory`, `Port`, `MemoryMb`, `JavaPath`, `AutoRestart`, `BackupIntervalHours` и `LastBackupUtc`. `Endpoint` вычисляется как `127.0.0.1:Port` и не записывается в JSON.

| Расположение | Содержимое |
| --- | --- |
| `%APPDATA%\MinecraftServerManager\settings.json` | Выбранный язык приложения. При отсутствии или повреждении файла используется английский. |
| `%APPDATA%\MinecraftServerManager\servers.json` | Список профилей. `ProfileStore.Save` записывает `.tmp` и заменяет основной файл. |
| `%APPDATA%\MinecraftServerManager\templates\templates.json` | Имя исходного файла и время импорта шаблона. |
| `%APPDATA%\MinecraftServerManager\templates\bedrock.zip` и `server.jar` | Локальные копии выбранных пользователем серверных файлов. |
| `<Directory>\server.properties` | Настройки конкретного сервера. При сохранении прежняя версия копируется в `server.properties.bak`. |
| `<Directory>\backups\*.zip` | Копии мира конкретного профиля. |
| `<Directory>\whitelist.json` или `allowlist.json` | Белый список Java или Bedrock; при прямом изменении сохраняется `.bak`. |

Шаблоны и профили не содержат сами миры. Папки серверов задаёт пользователь, поэтому перенос одного только `servers.json` не переносит серверы. `TemplateStore.Import` проверяет тип файла и наличие `bedrock_server.exe` или `META-INF/MANIFEST.MF` внутри архива, затем заменяет сохранённую копию. `TemplateInstaller` готовит новый сервер во временной соседней папке и переносит его в выбранный пустой каталог после успешной подготовки.

## Жизненный цикл сервера

`ServerManager.Start` запускает `bedrock_server.exe` из папки профиля либо Java с аргументами `-Xmx<MemoryMb>M -jar server.jar nogui`. Перед запуском Java проверяется `eula.txt`. Для процесса перенаправлены стандартный ввод, вывод и поток ошибок; журнал хранится в памяти и обрезается при превышении 200 000 символов. Приложение не сохраняет этот буфер на диск.

Возможные состояния: `Stopped`, `Starting`, `Running`, `Stopping`, `Restarting`, `Failed`. `Running` означает работающий процесс, а не проверенную готовность игрового сервера. `Stop` отправляет `stop`, ждёт до 30 секунд, затем при необходимости завершает дерево процесса. `StopAll` вызывается при явном выборе «Выход из приложения» в меню трея; кнопка закрытия окна скрывает его.

При неожиданном завершении с включённым `AutoRestart` менеджер ждёт три секунды и пытается запустить сервер снова. Лимит — три попытки в скользящем окне пяти минут. Ожидающий запуск отменяется при ручной остановке, удалении профиля и закрытии приложения. Доступ к журналу защищён блокировкой `StringBuilder`; операции с процессом координируются через `processGate` и словари по `Id` профиля.

## Настройки и согласованность

Сохранение параметров профиля в `MainWindow` проверяет название, порт, объём памяти и отсутствие конфликта портов для той же редакции. Затем обновляет `server-port` в `server.properties` и сохраняет JSON. При ошибке прежние значения профиля восстанавливаются; выполняется попытка восстановить прежний текст `server.properties`.

Текст `server.properties` сохраняется отдельной кнопкой. Если его `server-port` отличается от порта профиля, сохранение отклоняется. Поля профиля и текст файла имеют отдельные снимки изменений: при смене профиля, удалении из списка и выходе через трей приложение предупреждает о несохранённых правках. Запись `server.properties` выполняется через `.tmp`, рядом сохраняется `.bak` предыдущего файла.

## Управление игроками и трей

`MainWindow` показывает поля памяти и пути к Java только у Java-профилей и сохраняет их прежние значения при записи профиля Bedrock. `SimplePropertiesEditor` скрывает параметры, относящиеся только к другой редакции, даже если они присутствуют в `server.properties`; текстовый редактор оставляет весь файл доступным. Кнопка обзора «Открыть папку» запускает Проводник Windows для каталога выбранного профиля.

Кнопка «Удалить» в обзоре подтверждает точный путь и удаляет профиль вместе с файлами. `ServerFolderDeletion` запрещает удаление корня диска, защищённых системных каталогов и каталога приложения, корневой папки-ссылки, а также папок, пересекающихся с другим профилем. При рекурсивном удалении ссылки на каталоги удаляются без обхода их содержимого. Сервер должен быть остановлен; резервное копирование не должно выполняться. Сначала сохраняется удаление профиля, затем удаляются файлы; при ошибке профиль восстанавливается. Если удаление успело частично выполниться, папку нужно проверить вручную.

`ServerManager` разбирает ответы консольной команды `list` в список игроков онлайн в памяти. `MainWindow` запрашивает обновление примерно раз в 10 секунд при открытой вкладке игроков. Перед отправкой команд имена проверяются и заключаются в кавычки при необходимости. Для Java изменения списка на работающем сервере выполняются командами; при остановке можно удалить имя из `whitelist.json`, а для добавления нужен сервер, определяющий UUID. Bedrock при остановке использует `allowlist.json`. Переключатель списка изменяет `server.properties` и отправляет команду включения или выключения при работающем сервере.

Окно запускается развёрнутым. Кнопка закрытия скрывает его; `NotifyIcon` восстанавливает окно по двойному нажатию или через меню. Явный выход из трея проверяет несохранённые настройки, ждёт файловые операции, останавливает управляемые серверы и освобождает значок.

## Резервные копии

`ServerManager.CreateBackup` работает только при остановленном сервере. Для Java источник определяется по `level-name` из `server.properties` с запасным значением `world`; для Bedrock архивируется вся папка `worlds`. В архив попадает содержимое исходного каталога. Имя ZIP включает редакцию, дату, миллисекунды и случайный идентификатор. При ошибке незавершённый ZIP удаляется.

`RestoreBackup` принимает только ZIP из каталога `backups` данного профиля. Архив распаковывается во временный каталог рядом с миром; прежний мир временно переименовывается. Если замена не удаётся, код пытается вернуть прежний каталог. После успешной замены временная прежняя копия удаляется.

Расписание хранится в профиле: `0` означает выключено, интерфейс предлагает интервалы 6, 12 и 24 часа. Проверка идёт раз в минуту пока приложение работает; активный сервер и сервер, ожидающий автоперезапуска, пропускаются. После успешной копии обновляется `LastBackupUtc` и сохраняется список профилей. После ошибки повторная попытка откладывается на час в памяти приложения. Старые ZIP автоматически не удаляются. Архивирование и восстановление выполняются через `Task.Run`, а окно ждёт завершения этих операций перед закрытием.

## Обновления и развитие

`UpdateChecker` ограничивает одновременные проверки через `SemaphoreSlim`. Файл `%APPDATA%\\MinecraftServerManager\\update-check.json` хранит последний результат и время следующего разрешённого запроса UTC. Автоматическая и ручная проверки используют общий интервал не менее 15 минут даже после перезапуска. Заголовки `Retry-After` и `X-RateLimit-Reset` продлевают ожидание при ограничении GitHub. Если файл кэша записать не удалось, ограничение остаётся в памяти текущего процесса.

`UpdateChecker` запрашивает `releases/latest` у GitHub с тайм-аутом десять секунд, сравнивает тег релиза с версией сборки и передаёт ссылку на страницу релиза. Загрузка и установка обновления не реализованы.

При добавлении новой настройки профиля обновите `ServerProfile`, элементы формы в `MainWindow.xaml`, загрузку и сохранение полей в `MainWindow.xaml.cs`, оба файла локализации и документацию на двух языках. Если новая операция читает или меняет мир, учитывайте состояние процесса, обработку ошибок и выполнение файловой работы вне UI-потока. Серверные бинарные файлы Mojang/Microsoft в репозиторий и релиз приложения не включаются.
